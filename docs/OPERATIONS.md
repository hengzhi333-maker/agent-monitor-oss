# Operations

## Daemon Process

The daemon is a local workstation process. Keep the real runtime config in
`daemon/config.json`; it is intentionally ignored by git.

Windows:

```powershell
cd daemon
.\start-agent-monitor-daemon.ps1
```

The script reads `AM_PORT` or `config.json.port`, avoids starting a duplicate
listener on the same port, and writes local logs beside the daemon.

Windows service:

```powershell
cd daemon
.\windows\install-service.ps1
```

The installer uses `nssm.exe` when available, sets auto-start, stdout/stderr log
files, and log rotation. If you do not have NSSM, use:

```powershell
.\windows\install-service.ps1 -UseScheduledTaskFallback
```

That fallback installs a startup scheduled task with restart settings. Remove
either deployment with:

```powershell
.\windows\uninstall-service.ps1
```

Windows tray/control panel:

```powershell
cd daemon
.\windows\control-panel.ps1
```

The control panel reads local `config.json`, checks `/ping`, can start or stop
the daemon, opens `.agent-monitor.log.jsonl`, and exports
`/diagnostics/package` for support handoff.

PM2:

```powershell
cd daemon
npx pm2 start ecosystem.config.cjs
```

Docker:

```powershell
cd daemon
Copy-Item .\config.example.json .\config.json
docker compose -f docker-compose.example.yml up --build
```

Inside Docker, set `bindHost` to `0.0.0.0` so the container can receive traffic.
Restrict exposure at the host port, tailnet, token role, and
`remoteControl.allowedRemoteAddresses` layers. Workbench sessions run inside the
container, so install the required agent CLIs there and mount only intended
workspace directories.

systemd:

```bash
sudo cp daemon/systemd/agent-monitor.service.example /etc/systemd/system/agent-monitor.service
sudo systemctl daemon-reload
sudo systemctl enable --now agent-monitor
```

Edit paths, user, and environment for your machine before enabling the service.

## Transport

Preferred production layouts:

- Tailscale/LAN plus long random bearer token.
- Tailscale/LAN plus daemon TLS.
- Reverse proxy TLS in front of the daemon.

Do not publish the daemon directly to the public internet.
If `tls.cert` and `tls.key` are configured but cannot be read, the daemon exits
instead of falling back to cleartext HTTP.

## Android

The Android app starts `MonitorService`, a foreground service that keeps daemon
connections alive while the app is backgrounded. The service and UI share
`MonitorEngine`, so there is one connection loop per saved host.

The add-host flow has presets for Tailscale, USB `adb reverse`, and LAN. The app
also handles `agentmonitor://host?...` deep links from the daemon setup QR and
has an in-app QR scanner plus a local backup/import screen for the encrypted
host list. Exported host backups can also be password-encrypted with AES-GCM and
PBKDF2; after decryption they still contain tokens, so treat them as secrets.

Deep links generated by the daemon include a stable `identityKey`. When Android
imports the same workstation through USB, LAN, and Tailscale, it replaces the
existing host instead of creating duplicate entries. After moving from temporary
USB testing to Tailscale, use Settings -> `清理旧 USB 主机` to remove stale USB
hosts that still have a matching non-USB workstation.

Android emits daemon-sent alerts and local host-offline alerts. Local offline
alerts are delayed for 60 seconds and deduplicated to avoid repeated noise while
a workstation or VPN is reconnecting.

Android also emits local workbench notifications when a running workbench task
finishes, stops, fails, or remains running for more than 10 minutes.

## Tailscale Setup

Recommended private setup:

1. Install and sign in to Tailscale on the workstation and phone.
2. Bind the daemon to the workstation Tailscale IP when possible, or keep
   `0.0.0.0` with a strict token and `allowedRemoteAddresses`.
3. In Android, use the Tailscale preset and either MagicDNS (`workstation`) or the
   workstation `100.x` address.
4. Use `GET /setup/qr.svg?includeToken=1` only on a trusted screen and delete
   the QR file after import.

USB `adb reverse tcp:8765 tcp:8765` remains useful for temporary debugging but
does not survive unplugging or rebooting the phone.

The Android diagnostics screen checks the app version, daemon `/version`,
notification permission, `/ping`, token role, allowlist, Tailscale hints,
snapshot access, WebSocket connectivity, and CLI availability.

Samsung Secure Folder is a separate Android user/profile. If you installed a
test APK there, uninstall or clear data inside Secure Folder separately; the
main-profile app and ADB uninstall do not clean that copy.

## Release Signing

Copy `android/keystore.properties.example` to ignored
`android/keystore.properties`, then fill in local signing details. Release builds
enable R8 and resource shrinking and intentionally fail if signing is missing.

For a private deployment, generate a local signing identity:

```powershell
.\scripts\create-android-keystore.ps1
```

This writes ignored files under `android/`:

- `release.keystore`
- `keystore.properties`

Back up both files. Android uses the signing certificate as the app identity,
and future updates must be signed with the same key.

## Release Packaging

From the repository root:

```powershell
.\scripts\build-release.ps1 -AndroidVariant debug
```

The script runs daemon tests, runs `npm audit` against the official npm registry,
builds the selected Android APK, and creates a timestamped folder under `dist/`
with:

- `agent-monitor-debug.apk` or `agent-monitor-release.apk`
- `agent-monitor-daemon.zip`
- `README.md`, `SECURITY.md`, `LICENSE`, and `docs/`
- `release-manifest.json` with artifact names, SHA256 hashes, and whether tests
  and audit ran

Use `-AndroidVariant release` only after configuring signing credentials. Use
`-SkipAudit` only when the machine cannot reach the official npm registry and
record that exception in your release notes.

## Private Install and Upgrade

For a machine-local private deployment, copy the daemon package while preserving
runtime state:

```powershell
.\scripts\install-private.ps1 -InstallDaemonDependencies
.\scripts\upgrade-private.ps1
```

Both scripts preserve ignored runtime files such as `config.json`,
`.agent-monitor-history.sqlite`, `.agent-monitor-devices.json`, and structured
logs. To install the release APK over USB after building it:

```powershell
.\scripts\install-private.ps1 -InstallAndroidRelease
```

## Diagnostics and Logs

The daemon writes structured JSONL logs to `.agent-monitor.log.jsonl` with a
single rotated `.1` file. Export a diagnostic package from the repo root with:

```powershell
.\scripts\export-diagnostics.ps1
```

The package includes runtime metadata, masked network interface data, token role
summaries, device last-seen status, recent history, recent structured logs, and
recent audit entries.

Use Android's Diagnostics screen first for phone-side problems. Use
`/diagnostics/package` or `scripts/export-diagnostics.ps1` when you need a
workstation-side handoff bundle.
